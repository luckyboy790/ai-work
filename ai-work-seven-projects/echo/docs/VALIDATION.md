# 实际验证报告

日期：2026-09-18。该报告区分源代码存在、测试实际通过、运行受阻和未验证，不以测试脚本存在代替它被成功执行。

## 总体结论

**已交付：**完整应用源码、锁定版本的依赖声明、原生 Node 静态服务器、启动脚本、玩法/模型说明、测试代码和已有证据。

**已通过：**独立模拟 34 项 Node 测试，实际 Input/UI 模块的离线 Chromium 输入/界面检查，项目 JavaScript 语法检查。

**受阻：**制作环境的外部域名解析/联网下载不可用，Three.js 未能安装或复制；浏览器访问本地应用地址返回 `net::ERR_BLOCKED_BY_ADMINISTRATOR`；独立 WebGL2 探测返回 `null`。因此整场景没有被渲染、没有可作为游戏画面的截图、没有测量帧率，着色器也没有获得编译通过证据。

源码可以按启动说明在具备依赖下载和 WebGL2 的环境准备运行，但**本轮没有完成用户要求的端到端图形运行验收**。请勿把 ZIP 描述为“已在桌面和真机完整玩通”或“已离线预装所有依赖”。

## 1. 静态语法与服务启动

环境有 Node.js 22.16.0、npm 10.9.2、Python 3 与 Playwright/Chromium。

使用 `node --check` 检查应用模块、服务器、复制工具与 Node 测试源码；该检查不解析真实 Three.js 依赖，也不会编译 GLSL。Node 服务进程实际启动并输出本机/局域网入口，原日志见 `evidence/server.log`。浏览器网络访问被策略阻断，所以仅服务进程启动不是完整浏览器启动验收。

脚本 `npm ci` 的联网依赖下载未成功。本包 `vendor/` 中只有说明文件，需要在目标环境执行依赖准备命令后生成引擎。复制工具有版本检查和失败退出码，但没有以真实 Three.js 安装目录完成复制验证。

## 3. 实际执行的离线浏览器检查

执行：

```sh
python tests/offline_browser_check.py
```

输出：`evidence/offline-browser-report.json`。方法是在无网络离线页面中注入**真实应用的 Simulation、Input 和 UI 模块**，摄影机仅使用位置/旋转测试替身，没有加载 Three.js，也没有游戏场景。

实际收到并验证的输入与界面结果：

| 类别 | 通过项目 |
| --- | --- |
| 桌面键鼠 | 键盘前进至测试墙停止、摄影机不低于解析地面；沿墙横移；鼠标拖动改变角度；暂停清空输入；E/J 路由 |
| 触摸模拟 | Chromium CDP 同时发出两根触点，摇杆移动与环顾同时生效；松手停止；点击交互；触摸取消释放移动 |
| 中文界面 | 390×844 视口无横向溢出；七个设施面板生成对应读数与操作；触摸复苏按钮发送正确参数；手记曲线、长说明滚动与关闭；844×390 横屏设施动作/关闭可触达；显示时钟与模拟刻一致 |

## 4. 尝试但受阻的整场景检查

原目标是使用 `tests/browser_check.py` 导航本地游戏、用实际按键移动与拖动、观测并检查距离限制、脱水/复苏、等到覆灭、重试，再用触摸模拟复验。测试辅助接口只在 `?test=1` 下出现，其中定点设置用于到达设施，时间推进用于覆盖后果；不是人工游玩录像。

实际第一步导航即返回：

```text
net::ERR_BLOCKED_BY_ADMINISTRATOR
http://127.0.0.1:4173/?test=1
```

记录见 `evidence/browser-report.json`。没有修改浏览器安全策略、没有将未执行测试填成通过。单独采用离线模块测试作为低风险补充，不代替被阻断的完整应用导航。

## 5. 尚未验证及已知限制

完整 Three.js 初始化、真实 shader 编译、最终视觉构图、场景遮挡、三日/影子/地形的屏幕效果、所有可见墙体与碰撞对应关系、完整设施行走路线、DOM 与主循环结合后的每个结局/重试流程，均未完成真实渲染验收。

环境音代码仅合成，不含媒体加载，首次创建/恢复 AudioContext 由用户手势触发；未进行真实扬声器/耳机听感或平台兼容性检查。指针锁定有降级拖动方案，但跨浏览器实际锁定没有验证。

未测真实移动设备、Safari/Firefox、不同 GPU、长时间渲染内存、帧率和电池表现。自适应质量逻辑存在，但没有用本环境无法产生的 GPU 测量值为其背书。

已知实现简化包括有结构且周期重复的编排星历、有限种子扰动、群体人口的连续数值、代表性人物而非逐个真实代理、最强一颗太阳投阴影、无真实水面太阳反射或流体、没有行星潮汐撕裂/脱轨。它们在模型说明中明确列出。

## 6. 目标环境的复验顺序

完成 `npm ci`、`npm run vendor`、`npm start` 后，先确认出现真实三维场景而不是启动错误提示；再执行浏览器冒烟脚本。随后需要实际人工检查观星台—干仓—水池的行走路线、太阳接近/退远时的视听征兆、两场灾变之间的复苏和修仓，以及失败/重试后的状态和镜头重置。真实手机还需以双指同时移动/环顾、设施触摸和横竖屏操作复验。

以上是尚未执行的验收顺序，不是后续承诺或已经获得的测试证据。
